# Information Security and Confidentiality Policy

## 1. Scope and Objective

This policy establishes strict standards for protecting proprietary commercial strategies, client business models, pricing structures, and financial projections within the **Franchise Business Modeling & Intelligence Platform**.

---

## 2. Information Classification Standard

All information maintained within or generated by this repository is classified into four security tiers:

| Tier | Classification | Description & Examples | Storage & Handling Rules |
|---|---|---|---|
| **Tier 1** | **Public** | High-level platform vision, generic open-source frameworks, standard documentation. | May be published publicly if authorized. |
| **Tier 2** | **Internal Proprietary** | Calculation algorithms, internal templates, general industry benchmarks, testing tools. | Restricted to authorized internal contributors and analysts. |
| **Tier 3** | **Client Confidential** | Working assumptions, non-final drafts, product profiles, sales targets, and market research for named clients (e.g., `clients/tmk-it-solutions/`). | Restricted to authorized team members assigned to the client engagement. |
| **Tier 4** | **Restricted / Secret** | Client bank accounts, customer PII, signing keys, API tokens, executed commercial contracts. | **STRICTLY PROHIBITED from Git repository.** Must reside exclusively in enterprise secrets vaults or encrypted document storage. |

---

## 3. Git Access Controls and Branch Protection

1. **Repository Visibility:** The repository must be configured as **Private** across all source code hosts (GitHub, GitLab, Bitbucket).
2. **Branch Protection Rules:**
   - Direct pushes to `main` and `master` branches are blocked.
   - All merges require a Pull Request with at least one approved peer review (Analyst 1 or Analyst 2).
   - Automated CI quality checks (`validate_repo.py` and `pytest`) must pass before merging.
3. **Least Privilege Access:** Access permissions are provisioned on a project-need basis. External contributors or client observers are not granted write access to core frameworks.

---

## 4. Secret Management Protocol

- **Zero-Secret Commitment:** No API keys, passwords, connection strings, or cryptographic private keys may be committed to this repository.
- **Automated Scanning:** Pre-commit hooks and CI pipelines inspect commits for high-entropy strings, AWS/GCP tokens, and secret patterns.
- **Handling Accidental Commits:** If a credential is committed, it must be considered immediately compromised and rotated immediately, followed by git history rewriting using `git-filter-repo`.

---

## 5. Client Data Isolation & Migration to SaaS Storage

For **Platform V0.1**:
- The inaugural client workspace (`clients/tmk-it-solutions/`) houses authorized non-sensitive commercial assumptions, publicly verifiable product characteristics, and non-final working drafts.
- No client end-user personal data (PII) or banking credentials are stored.

**Pre-Requisite for Onboarding External Clients (Migration to Cloud Storage):**
Before onboarding external commercial enterprises beyond internal portfolio companies:
1. Client workspaces containing proprietary commercial agreements must transition to dedicated encrypted S3/Azure Blob storage containers backed by customer-managed keys (CMK).
2. Client-specific databases will utilize PostgreSQL Row-Level Security (RLS) with AES-256 encryption at rest.
3. Git will store only versioned schemas and generic modeling algorithms; client operational data will reside exclusively in the cloud SaaS tier.
