# Technical Documentation & Markdown Standards

## 1. Markdown Standards
1. Use GitHub Flavored Markdown (GFM).
2. Use GitHub alerts (`> [!NOTE]`, `> [!IMPORTANT]`, `> [!WARNING]`, `> [!CAUTION]`) strategically to highlight key caveats.
3. Every document must have a title heading, document control summary, and explicit section numbering.
4. Internal relative links must point to valid local markdown files or schemas.

## 2. Document Status Tags
All working documents must clearly indicate their status:
- `[DRAFT]`: Initial working creation.
- `[PEER APPROVED]`: Reviewed and confirmed by peer analyst.
- `[MODELING APPROVED]`: Mathematical calculations verified.
- `[CLIENT APPROVED]`: Formally signed off by client executive.
